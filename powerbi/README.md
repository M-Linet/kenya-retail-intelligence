# Power BI: model specification and build guide

> **Status:** the dashboard is built as a **Power BI project** (`SavannaFresh.pbip`, plus the `SavannaFresh.SemanticModel/` and `SavannaFresh.Report/` folders). It is stored as text (TMDL model, PBIR report), so Git shows meaningful diffs. Both parts are generated by code:
> - `scripts/build_pbip_model.py` writes 10 tables (Power Query CSV sources driven by a `DataFolder` parameter), 11 relationships, a marked date table and 71 measures.
> - `scripts/build_pbir_report.py` writes the 4 pages (58 visuals) in the editorial style defined in `scripts/pbi_editorial.py`.
>
> The model was loaded and refreshed in Power BI Desktop (Nov 2026 build), and a DAX query confirmed that the KPIs match `kpi_reconciliation.csv` exactly.
>
> To open it: run `python -m src.export_powerbi` (or unzip the CSV extract into `data/processed/powerbi/`), open `SavannaFresh.pbip`, set the `DataFolder` parameter if your path differs (*Transform data → Edit parameters*), then click **Refresh**. To get a single file, use *File → Save as → .pbix*.
> `screenshots/page1_…` to `page4_…` were taken from Power BI Desktop after refresh. The images whose names start with `prototype_` are the earlier Python layout prototypes.

The sections below document the model so that every design choice can be explained.

## 1. Get the data in

**Option A: connect to PostgreSQL (recommended).** In Power BI, choose *Get Data → PostgreSQL database*, server `localhost`, database `retail_intel`, mode **Import**. Select every view in the `powerbi` schema: `dim_date`, `dim_branch`, `dim_product`, `dim_customer`, `dim_promotion`, `fact_sales`, `fact_inventory`, `fact_inventory_position`. Then add `promo_performance` from CSV (Option B). Power BI may ask you to install the Npgsql provider the first time.

**Option B: CSV files.** Run `python -m src.export_powerbi`, then *Get Data → Text/CSV* for each file in `data/processed/powerbi/`. Set data types in Power Query: dates as **Date**, money columns as **Fixed decimal**, `is_*` columns as **True/False**.

## 2. Data model (star schema)

```
                 dim_date (date)
                /       \
   fact_sales ─┘         └─ fact_inventory ── (snapshot_date)
     │  │  │  │                  │   │
     │  │  │  └ dim_promotion     │   └ dim_product
     │  │  └ dim_customer         └ dim_branch
     │  └ dim_product
     └ dim_branch
   fact_inventory_position ── dim_branch, dim_product   (latest stock position only)
   promo_performance ── dim_product                     (one row per promotion)
```

| From (one side) | To (many side) | Key | Direction |
|---|---|---|---|
| dim_date[date] | fact_sales[sale_date] | date | single |
| dim_date[date] | fact_inventory[snapshot_date] | date | single |
| dim_branch[branch_id] | fact_sales, fact_inventory, fact_inventory_position | branch_id | single |
| dim_product[product_id] | fact_sales, fact_inventory, fact_inventory_position, promo_performance | product_id | single |
| dim_customer[customer_key] | fact_sales[customer_key] | customer_key (`ANON` = no loyalty card) | single |
| dim_promotion[promotion_id] | fact_sales[promotion_id] | promotion_id | single |

Modelling decisions and why:
- **Mark `dim_date` as a date table** (*Table tools → Mark as date table → date*). Time-intelligence functions such as `DATEADD` need it.
- **Single-direction filters only.** Bi-directional relationships between two fact tables through shared dimensions create ambiguous paths and slow, surprising totals.
- **Anonymous customers get a real dimension row (`ANON`)** instead of a blank key, so slicing by segment never silently drops 38% of revenue.
- **Stock is semi-additive.** `fact_inventory` holds balances. Summing them across weeks is meaningless, so every stock measure picks a date (latest snapshot) or averages over weeks.
- **Hide** the foreign-key columns in the fact tables and all raw numeric columns. Report authors should only use measures.
- Sort `dim_date[month_short]` by `month_number` and `day_short` by `iso_dow`.

## 3. Measures
Paste from `dax_measures.dax` into a `_Measures` table. Key definitions:

| Measure | Business definition |
|---|---|
| Revenue | Net revenue after all discounts (KES; shelf prices treated as VAT-exclusive) |
| Gross Profit / Gross Margin % | Revenue − standard cost of goods; margin = GP ÷ Revenue (ratio of totals) |
| Transactions / ATV | Distinct receipts; Revenue ÷ receipts |
| Non-Promo Discount % of Sales | Discounts not linked to a promotion ÷ gross sales (markdowns + overrides) |
| Revenue YoY % / LFL YoY % | Against the same dates last year; LFL excludes branches opened after 1 Nov 2024 |
| Stockout Rate % | Share of branch-product-weeks whose Sunday closing stock was 0 |
| Inventory Turnover (annualised) | COGS ÷ average weekly stock value at cost, scaled to 52 weeks |
| Slow-Moving Stock Value | Latest stock at cost where cover > 26 weeks, or no sales in 12 weeks |
| Promo Incremental GP | From SQL: promotion GP − 28-day full-price baseline GP × promotion days |

## 5. Design and accessibility
- **Story first:** a kicker, a headline that states the finding (Georgia serif) and a two-line standfirst. One hero chart carries the evidence, and two smaller charts support it.
- **Right column:** big-number tiles with ▲/▼ year-on-year deltas, then a **"What we'd do"** box.
- **Kenyan identity:** a deep-green masthead with a maize-gold accent and a kikoi-style woven stripe under it (`kikoi_strip.png`), on a warm paper background.
- **Notes on the charts:** a dashed line marks Ruiru's opening on the sales trend.
- **Colour has one job per chart:** blue = focus, orange = the problem, grey = context.
- **Colour-blind safe:** blue `#2a78d6` and orange `#eb6834` pass the palette validator on white: worst-case separation under simulated protanopia, deuteranopia and tritanopia is ΔE 24.7 (target ≥ 8), with at least 3:1 contrast. There is no red/green pairing. Colour is never the only cue: bars carry data labels outside the bar, subtitles name what the colours mean, status uses text plus symbol, and deltas use arrows.

4. Select one month: Revenue YoY % should match `reports/sql_outputs/q02_monthly_revenue_mom.csv` against the same month last year.
5. Slice by customer segment: the `Anonymous` row must appear, and the segments must sum to the total.
